## 1. 프로젝트와 시연 범위

ARGUS-X는 기존에 제공된 **보안 Agent의 로컬 웹 UI·서버 구조**를 유지하고, Windows PC 자원 및 운영체제 보안 진단 기능을 추가한 **로컬 관제 대시보드**다. 시연에서 **핵심 3가지**는 (1) 기록 보기, (2) 내 PC 상태, (3) 위험 알림이다. 각 기능은 `보호 현황`의 진입 동선으로 제시하며, 2번을 시연할 때 **추가 Windows 네트워크·보안 관제** 화면도 보여 준다.

- **화면 틀:** 2일차 PC 현황 상단 **CPU / 메모리 / 디스크 / 조회 상태** 4개 카드, 아래 추이·수치 설명·기록. 3일차 관제 상단 **네트워크 / 방화벽 / Windows 경고·오류 / SDP 상태** 4개 카드, 아래 추이·기록. 4일차 학생 요약은 **기록 보기 / 내 PC 상태 / 위험 알림 / 재조회 상태** 4개 카드.
- **실행 방식:** Windows PC의 `on-client` 폴더에서 직접 실행, 일반 사용자 권한·읽기 전용. 로컬 브라우저 주소는 `http://127.0.0.1:5189/`. 다른 PC의 `127.0.0.1`은 **그 PC 자체**다.
- **이번 시연에서 하지 않을 일:** `npm run package-app` 및 다른 포장 명령, 설치파일 제작, 시스템 보안 설정/방화벽 변경, 공격·침투 시연, 관리자 권한 상승, 미승인 SDP 연결 설정·비밀키 입력.
- **원본 보존:** `C:\github\aleph-defense-starter`, 별도 작업 사본 `C:\github\ARGUS-X-22-repro`, 이전 제출 커밋/`main`은 삭제·이동·덮어쓰지 않는다.

## 3. 완성본 시연 동선 — 핵심 3가지

### 0. 시연 준비 — 1분

1. Windows PowerShell에서 `on-client` 프로젝트 폴더와 Node.js 버전(권장 `v24.19.0`; 시작 도구는 22~24 지원)을 확인한다.
2. 학생 모듈·PC 보안 모듈 구문 검사 후 시작 스크립트로 실행한다(6절 명령 참조). 실행 화면의 **“케셰브가 켜졌습니다”**는 기존 실행 스크립트 명칭이다.
3. 브라우저의 `http://127.0.0.1:5189/` → **보호 현황**에 접근한다. 1~4일차 영역이 표시되는지 확인하고, 조회 전 `확인 불가`를 성공으로 해석하지 않는다.

### 핵심 1. 기록 보기 — 약 1분

- **동선:** 보호 현황 → **1. 기록 보기** → **보안 기록** 탭 → 학생 기록 표시 영역.
- **보여 줄 것:** 제공된 보안 기록 탭 및 내가 정리한 핵심 기능 바로가기/기록 상태. 가능한 경우 조회 상태, 분류·기록 표시와 오류 안내를 보여 준다.
- **확인된 사실:** 화면 렌더링은 확인했으나 원천 데이터는 `ENGINE_NOT_CONNECTED`. **실제 SDP 사건 기록을 불러온 성공 사례는 없다.**
- **시연 멘트:** “보안 기록을 표시할 화면은 준비되어 있지만 현재 기존 SDP 어댑터가 미연결이므로 실제 원천 기록을 확인했다고 표시하지 않습니다.”

### 핵심 2. 내 PC 상태 + 로컬 보안 관제 — 약 3~4분

**A. 내 PC 상태**
1. 보호 현황 → **2. 내 PC 상태**에서 **CPU·메모리·디스크·조회 상태 카드 4개** 확인.
2. **PC 상태 다시 조회** 클릭 → 실제 수치·단위(%, GiB)·측정 시각, 조회 성공/실패를 확인.
3. 같은 버튼을 **두 번째** 누른 뒤 같은 종류의 직전 성공 조회 대비 변화량과 아래 **추이·설명·타임라인·필터**를 보여 준다.
4. 실패 값은 `0`이나 최근 정상 측정으로 꾸미지 않고 `확인 불가`로 보여 준다. 브라우저 메모리 기록은 새로고침으로 초기화될 수 있다.

**B. 네트워크·보안 관제(같은 보호 현황의 별도 3일차 영역)**
1. **네트워크·보안 다시 조회** 클릭 → **네트워크·Windows 방화벽·Windows 경고/오류·SDP** 카드 4개 확인.
2. 화면에 표시된 **Windows PC 조회 성공 4/4종**과 System/Application의 **최근 24시간** 개별 기록·조회 시각 확인. 필요하면 종류별 필터를 바꾼다.
3. 실제로 검증된 응답은 **네트워크·방화벽·System·Application** 4가지. **SDP 카드 미연결은 별도이며 4/4 성공에 포함되지 않는다.**
4. System/Application 로그 경고·오류 증감은 최근 24시간 집계의 차이일 뿐, 공격 탐지나 사고 급증 판정이 아니다.

**이전 실측 기록(설명용 예시가 아니라 2026-10-28 실제 조회 당시 값):**

| 확인 항목 | 실제 보고 값 | 출처와 한계 |
|---|---:|---|
| CPU 사용률 | 95.6% | 사용자 PC의 과거 측정 시점; 지금 상태가 아님 |
| 메모리 사용 추정량 | 14.78 GiB | 사용자 PC의 과거 측정 시점 |
| 디스크 여유 | 246.71 GiB | 프로젝트 파일시스템의 과거 사용 가능 공간 |
| System 최근 24시간 | 경고 **160건**, 오류 **20건** | 수정본 실행 후 사용자 전달 **실제 집계** |
| Application 최근 24시간 | 경고 **9건**, 오류 **5건** | 수정본 실행 후 사용자 전달 **실제 집계** |

> **주의:** 위 수치는 각 실행·시점의 실측 기록으로 **시연 중 고정 출력하거나 기본값으로 넣지 않는다**. 최종 시연에서는 버튼을 눌러 **시연 PC에서 그때 다시 조회한 값**을 읽는다. 예제 데이터를 사용할 때에는 반드시 `demo / 예제`라고 표시한다. IP·DNS·게이트웨이 등 환경 상세정보는 제출 캡처에서 가린다.

### 핵심 3. 위험 알림과 실패 대응 — 약 1~2분

- **동선:** 보호 현황 → **3. 위험 알림** → **학생 상태·알림 표시**.
- **보여 줄 것:** 기록 보기 / 내 PC 상태 / 위험 알림 / 기록 재조회 상태 **4개 카드**, **기록 다시 조회** 버튼, 오류 코드·다음 행동.
- **확인된 사실:** 사용자 본인 PC의 스크린샷에서 기존 `renderStatus` 실행 오류가 사라졌고 카드 및 버튼이 나타남. **Tab 초점 표시 및 Enter 키 재조회 실행**을 본인 PC에서 확인. `ENGINE_NOT_CONNECTED` 시 `확인 불가`와 다음 조치 표시.
- **보여 주지 못하는 것:** 실제 XDR 공격 감지, 실시간 알림 발송, SDP 사건 조회·차단·SOAR 집행의 성공. 화면에 `위험 알림`이라는 제목이 있다고 원천 탐지가 검증된 것은 아님.
- **시연 멘트:** “연결 실패를 성공처럼 보이지 않고 코드와 다음 행동을 안내합니다. 원천 탐지 및 알림 전송은 아직 별도 검증이 필요합니다.”
